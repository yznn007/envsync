EnvSync M2 测试向量 —— HPKE 设备信封（Key Envelope）
====================================================================

⚠️  以下全部私钥、临时私钥与数据密钥都是硬编码的测试专用假值，
    仅供测试，绝不用于生产。

来源测试：crates/envsync-crypto/tests/vectors.rs
          fn key_envelope_wire_vector_is_frozen()
复现命令：cargo test -p envsync-crypto --test vectors key_envelope_wire_vector_is_frozen
规范说明：docs/security/vault-format.md §4

⚠️  审计待办：本实现尚未与 RFC 9180 附录 A.3 的官方向量做互操作验证。
    见 docs/security/test-vectors/README.md §6「TODO-for-audit」。
    本文件是**回归向量**，只能证明「格式没漂移」，不能证明「符合 RFC 9180」。

--------------------------------------------------------------------

aad = canonical_cbor([version, suite, workspace_id, recipient, epoch, enc])

aad 与完整对象的区别：数组头 0x86 vs 0x87，且不含最后一项 ciphertext。

info 与 aad 的分工：workspace_id / recipient / epoch 三项被**两次**绑定
（一次经 info 进密钥，一次经 aad 进认证标签）；enc 只由 aad 绑定——它已经
通过 kem_context 影响了 shared_secret，不需要再进 info。


4. 密钥派生链（RFC 9180 §4.1 + §5.1，base 模式）
--------------------------------------------------------------------

记
  LabeledExtract(salt, label, ikm)
      = HKDF-SHA256-Extract(salt, "HPKE-v1" ‖ suite_id ‖ label ‖ ikm)
  LabeledExpand(prk, label, info, L)
      = HKDF-SHA256-Expand(prk, I2OSP(L,2) ‖ "HPKE-v1" ‖ suite_id ‖ label ‖ info, L)

第一步 DHKEM 封装（suite_id = 4b454d0020）

  1. esk           = ephemeral_secret（本向量为固定值；生产为 OsRng）
     enc           = X25519(esk, basepoint)
                   = 261cd9cd2e935f9c2455876a80f02a4d6786b8ab877f07227737ca0b577bf161
  2. dh            = X25519(esk, pkR)，随后检查非全零（贡献性）
  3. kem_context   = enc ‖ pkR                                  （64 字节）
  4. eae_prk       = LabeledExtract("", "eae_prk", dh)          （32 字节）
  5. shared_secret = LabeledExpand(eae_prk, "shared_secret", kem_context, 32)

第二步 base 模式 key schedule（suite_id = 48504b45002000010003）

  6.  psk_id_hash          = LabeledExtract("", "psk_id_hash", "")     （32 字节）
  7.  info_hash            = LabeledExtract("", "info_hash", info)     （32 字节）
  8.  key_schedule_context = 0x00 ‖ psk_id_hash ‖ info_hash            （65 字节）
  9.  secret               = LabeledExtract(shared_secret, "secret", "")（32 字节）
  10. key                  = LabeledExpand(secret, "key", key_schedule_context, 32)
  11. base_nonce           = LabeledExpand(secret, "base_nonce", key_schedule_context, 12)

第三步 AEAD（seq = 0，因此 nonce = base_nonce）

  ciphertext = ChaCha20Poly1305-Seal(key, base_nonce, aad, data_key)

导出接口（exporter_secret）在 M2 用不到，未派生。

7. 怎么核对
--------------------------------------------------------------------

a) 逐字节比对第 2、3、5 节：
   cargo test -p envsync-crypto --test vectors key_envelope_wire_vector_is_frozen

b) 独立复现 enc：用任意 X25519 实现算 X25519([0x53; 32], basepoint)，
   结果应等于第 6 节的 [5]。

c) 独立复现整条派生链：按第 4 节逐步计算，最后用 ChaCha20-Poly1305 打开
   第 6 节的 ciphertext，应得到 [0x33; 32]。这一步不依赖 EnvSync 的任何代码，
   只需要 X25519 + HKDF-SHA256 + ChaCha20-Poly1305 三个标准原语。

d) 攻击路径自检（对应 tests/device_envelope.rs）：
   - 用另一台设备的私钥打开        → RecipientMismatch
     （only_the_target_device_can_open）
   - 交换两台设备的信封            → 失败（swapping_two_devices_envelopes_fails）
   - 把 epoch 改成别的值           → 失败（epoch_downgrade_fails）
   - 把 workspace 改成别的         → 失败（cross_workspace_replay_fails）
   - 翻转 ciphertext / enc 任意一位 → 失败
     （flipping_any_ciphertext_bit_fails、flipping_any_enc_bit_fails）

能证明什么：信封线格式、info/aad 的字段与顺序、派生链的每一步与冻结那天一致。
不能证明什么：**不能证明本实现与 RFC 9180 一致**。见 README.md §6 TODO-for-audit。
