EnvSync M2 测试向量 —— 设备身份与域分隔签名
====================================================================

⚠️  以下全部私钥种子都是硬编码的测试专用假值，仅供测试，绝不用于生产。

来源测试：crates/envsync-crypto/tests/vectors.rs
          fn device_identity_vector_is_frozen()
复现命令：cargo test -p envsync-crypto --test vectors device_identity_vector_is_frozen
规范说明：docs/security/vault-format.md §1、§3

1. 固定输入
--------------------------------------------------------------------

x25519_secret   5151515151515151515151515151515151515151515151515151515151515151
                32 字节。测试常量 [0x51; 32]。
                含义：设备的 X25519 私钥（只用于接收 HPKE 设备信封）。

ed25519_secret  5252525252525252525252525252525252525252525252525252525252525252
                32 字节。测试常量 [0x52; 32]。
                含义：设备的 Ed25519 私钥种子（只用于签名）。

                ⚠️ 两把私钥职责严格分离；生产环境它们只能存在于系统安全存储
                   （SecurePurpose::DeviceKemKey / DeviceSigningKey）。

domain          "membership-event"（16 字节 ASCII）
                含义：签名的用途标签。它进入待签结构，因此一枚成员事件签名
                      无法被复用成快照签名或信封签名。
                常量：envsync_core::membership::MEMBERSHIP_SIGNATURE_DOMAIN

workspace_id    11111111-1111-4111-8111-111111111111
                线上编码：11111111111141118111111111111111（16 字节）

payload         "test-vector-payload"（19 字节 ASCII）
                含义：被签名的内容。在成员链里，这一项是
                      MembershipEvent::signing_payload() 的输出。


2. 派生的公开材料
--------------------------------------------------------------------

x25519_public   ad908a8a708aca07588cda7c4ed3e44d4966a80a9abb2f1e4bbac53c67414e34
                = X25519(x25519_secret, basepoint)，32 字节

ed25519_public  2012cb90ca60e8e5d8daf66e2272d2233e0486d557e8c66141ed8920177d7eb7
                = Ed25519 公钥，32 字节

device_id       e3009d665bf8f968e99bc47aa11152c3ab0c7c0cfb1d57d554628e1d912364ec
                = BLAKE3_domain("envsync:device:v1", x25519_public ‖ ed25519_public)

                其中 BLAKE3_domain(domain, payload) 的定义（Digest32::domain_hash）：
                    BLAKE3( domain_utf8 ‖ 0x00 ‖ u64_be(len(payload)) ‖ payload )

                这里 domain = "envsync:device:v1"（17 字节），
                     payload = 64 字节（两把公钥拼接），
                     长度前缀 = 0000000000000040

                改动任意一把公钥的任意一位都会改变 device_id
                （测试 flipping_any_public_key_bit_changes_device_id）。

4. 输出：签名
--------------------------------------------------------------------

signature   1b79f0414676e668652d52a419cabef324728c191cc206b6e5b4800fe582f19a
            c7f4daa7ad6102677ac6d36e445137db4f33c3c51572942b658de473c875d10a
            64 字节。

Ed25519 是确定性签名（RFC 8032）：相同私钥 + 相同消息恒得相同签名，
因此签名本身可以被冻结，不需要注入任何随机量。

验签使用 ed25519_dalek 的 verify_strict，它额外拒绝小阶公钥与带扭转分量的
签名，从而排除签名可塑性（同一条消息存在多枚都合法的签名）。

6. 怎么核对
--------------------------------------------------------------------

a) 逐字节比对第 2、3、4 节：
   cargo test -p envsync-crypto --test vectors device_identity_vector_is_frozen

b) 独立复现 device_id：用任意 BLAKE3 实现算
   BLAKE3("envsync:device:v1" ‖ 0x00 ‖ 0000000000000040 ‖ x_pub ‖ ed_pub)
   结果应等于第 2 节的 device_id。

c) 独立验签：用任意 Ed25519 实现，以 ed25519_public 验证第 4 节的签名
   对第 3 节的 149 字节消息成立。这一步不依赖 EnvSync 的任何代码。

d) 攻击路径自检（对应 tests/device_identity.rs）：
   - 把 workspace_id 换掉 → 验签失败（cross_workspace_replay_is_rejected）
   - 把 payload 改一位   → 验签失败（modified_payload_is_rejected）
   - 把 domain 换掉      → 验签失败（different_domain_is_rejected）
   - 用另一台设备的公钥  → 验签失败（wrong_signer_is_rejected）
   - 翻转签名任意一位    → 验签失败（flipping_any_signature_bit_is_rejected）

能证明什么：DeviceId 的派生规则、待签结构的字段与顺序、签名结果与冻结那天一致。
不能证明什么：不能证明 Ed25519 本身正确——那由 ed25519-dalek 及其上游向量负责。
